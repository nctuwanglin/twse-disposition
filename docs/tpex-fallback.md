# TPEx 處置公告備援

主來源為 `/www/zh-tw/bulletin/disposal`；連線/JSON 抓取失敗後，改用官方
`https://www.tpex.org.tw/openapi/v1/tpex_disposal_information`。
主來源格式驗證失敗仍中止，不掩蓋未知 schema 變更。

HTTP 520–524 與既有暫時性錯誤最多各端點 3 次嘗試，退避 1、3 秒，
每次連線 timeout 15 秒。403/404 不重試。沒有無限重跑或關閉 TLS 驗證。

OpenAPI 沒有獨立產製日期及完整查詢區間證明，因此採保守防線：

- 必要欄位、處置日期須有效。
- 一般股票最新公告日必須等於報價取得的目標交易日；不能以執行日替代。
- 空陣列、只有非一般股票、過期或未來公告均拒絕。
- 必須可讀取既有 dispo.json，且其日期不得超過目標日。
- 上一版 active/upcoming 中 TPEx 尚未到期事件，須在備援中逐筆存在，
  核對證券代號、公告日、處置起迄日；只比對，不混入舊資料。
- 備援不能證明絕對完整性；上述檢查降低漏資料風險，不取代原有發布驗證。
  當日沒有一般股票新公告、官方更正/撤銷舊事件時可能保守拒絕，須查核官方資料。

採用端點與 fallback_reason 記入 sources.tpex_disposal，隨快照與健康狀態保留。
兩端失敗時維持 ok=false，既有發布流程中止。重試次數與錯誤寫入 Actions log。
